Documentation

The whole interface, on one sheet.

Everything below is the public surface. There is no hidden state, no clock, no file and no socket: a value goes in, bytes come out.

Install

moon add moonbitstack/moonfory

In moon.pkg:

import {
  "moonbitstack/moonfory",
}

The package is reached as @lib. Its dependencies are moonbitstack/moonvar for the numbers and moonbitstack/moondate for the time types; nothing else is pulled in.

The four verbs

A value goes in and comes out through dumps and loads. dump and load do the same over a Buffer or a Reader you already hold, for when a message is one part of a larger stream. 

let bytes : Bytes = @moonfory.dumps(value)
let value : T     = @moonfory.loads(bytes)

@moonfory.dump(value, buffer)
let value : T = @moonfory.load(reader)

One value, and then the end. loads reads exactly one value and then insists the message is finished. Two values in one buffer are a Trailing error, not a silent truncation.

Implementing Codec

A type joins in by implementing Codec. write_data writes the body only: the type ID belongs to whoever knows the schema, so a list element and a struct field each name their own type without the body repeating it. 

pub impl Codec for UserId with fn ty(_self) {
  TypeId::Int64
}

pub impl Codec for UserId with fn write_data(self, w) {
  w.write_i64(self.0)
}

pub impl Codec for UserId with fn read_data(r, _ty) {
  UserId(r.read_i64())
}

Bool, Int, Int64, UInt, UInt64, Byte, Float, Double, String, Bytes, Array[T], Map[K, V] and Value already implement it.

Strings are written as UTF-8. A reader also accepts LATIN1 and UTF-16, because pyfory writes LATIN1 for ASCII; only the writer's choice is fixed here.

Numbers, in one place

Int is written as INT32, Int64 as INT64, UInt as UINT32 and UInt64 as UINT64. The reader is looser on purpose: it accepts any width of the same signedness, so a peer's VARINT64 arrives as an Int without a byte of conversion. A 64-bit value asked for as a 32-bit type is refused rather than truncated.

Precedence. A call has three places to say what it wants. The library preset (config) is the floor. A Config passed as config= replaces it wholesale. The flat mirrors — xlang=, track_ref=, check_string=, depth=, fields=, graph= — then override single fields of that result. When a Config and a flat mirror disagree, the flat mirror wins, unless wins=Base is passed, in which case the record wins. A disagreement is silent by default; clash=Panic turns it into a Clashed error, and clash=Handle(f) lets you arbitrate. 

@moonfory.dumps(v, track_ref=true)
@moonfory.dumps(v, config=my_config, depth=8)
@moonfory.dumps(v, config=my_config, xlang=false, clash=Panic)

Shared and circular values

MoonBit has no object identity to track, so a value meant to be shared is marked explicitly, with a key you choose. The first write emits the body; later writes emit a back-reference. A cycle read back is stitched together through the reader's node table, and a cycle that cannot be resolved is a Cyclic refusal rather than a hang. 

let once  = @moonfory.shared(7, "the same string")
let twice = [once, once]   // two references, one body
let bytes = @moonfory.dumps(twice, track_ref=true)

Turn track_ref on for both ends, or neither: a reader that is not tracking reads the first body and then a flag it does not expect.

The row format

The row format trades a little space for random access: eight bytes per field, whether the field needs them or not, so field i is always at bitmap + i × 8. A reader takes one field and leaves the rest alone. 

let schema = @moonfory.RowSchema::new([
  { name: "id",   ty: @moonfory.RowType::Int64,  nullable: false },
  { name: "name", ty: @moonfory.RowType::String, nullable: false },
  { name: "age",  ty: @moonfory.RowType::Int32,  nullable: true  },
])

let row = @moonfory.Row::new(schema)
row.set(0, @moonfory.RowValue::Int64(7L))
row.set(1, @moonfory.RowValue::String("ada"))
row.set(2, @moonfory.RowValue::Null)

let cur = @moonfory.RowCursor::new(row.finish()[:], schema)
cur.get_field(1)   // RowValue::String("ada")
cur.is_null(2)     // true

The layout is the specification's standard variant: a null bitmap rounded to eight bytes, one eight-byte slot per field, then the variable data. An array keeps fixed-width elements at their natural width and variable ones as offset-and-size pairs; a map is a key array and a value array; a nested struct is a whole row inside the variable region.

The compact variant is not here. It is Java-only, so a cross-language implementation has no peer to agree with.

Time

Through moonbitstack/moondate, so a MoonBit program never spells out epoch seconds: 

let date   = @moonfory.date_of_days(19_000L)              // DATE
let moment = @moonfory.moment_of_parts(1_700_000_000L, 0) // TIMESTAMP
let span   = @moonfory.span_of_parts(3L, 500_000_000)     // DURATION
@moonfory.dumps(moment)                                     // and back

Nanoseconds are always the sub-second part, in [0, 1e9), so a value of 1.5 seconds is (1, 500_000_000) and a negative span borrows a second rather than carrying a negative nanosecond field.

What is deliberately not here

ThingWhy not
Compatible struct mode (28, 30)needs a schema registry to reconcile two type definitions; that belongs with moonmodel, not inside a codec
FLOAT8 / FLOAT8_ARRAY (16, 56)no peer in reach writes them; when one does, the table has the code
Writing a shared reference from a ValueValue has no identity to point at; use Shared[T] with an explicit key
Reading a struct without its schemathe schema is the user id's meaning; loads(schemas=[...]) supplies it

Each refusal is a Refused variant with the offset that produced it, so a malformed message names where it stopped rather than "invalid input".

Implemented from the cross-language specification, the row format specification and the type mapping — not from another implementation's source.
